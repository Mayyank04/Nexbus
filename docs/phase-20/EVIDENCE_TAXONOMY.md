## 1. THE NINE CANONICAL EVIDENCE CLASSIFICATIONS

NEXBUS strictly rejects binary "real vs fake" distinctions. Every data record displayed across the platform must be assigned to one of nine explicit, mutually exclusive classifications:

```
┌────────────────────────────────────────────────────────────────────────┐
│                      NEXBUS EVIDENCE TAXONOMY                          │
├─────────────────────┬──────────────────────────────────────────────────┤
│ Classification      │ Operational & Epistemological Definition         │
├─────────────────────┼──────────────────────────────────────────────────┤
│ OBSERVED            │ Directly recorded from physical transit sensors   │
│                     │ or documented field audit observations.          │
├─────────────────────┼──────────────────────────────────────────────────┤
│ VERIFIED_EXTERNAL   │ Obtained from published official records (DTC,   │
│                     │ OTD, DMRC, CPCB, Census) and checksum-verified.   │
├─────────────────────┼──────────────────────────────────────────────────┤
│ DERIVED             │ Calculated deterministically from verified       │
│                     │ input records using published formulas.          │
├─────────────────────┼──────────────────────────────────────────────────┤
│ ESTIMATED           │ Statistical approximation based on sampling      │
│                     │ distributions (e.g. ETM ticket boarding curves). │
├─────────────────────┼──────────────────────────────────────────────────┤
│ PREDICTED           │ Future or unobserved state output by machine     │
│                     │ learning models (ST-GNN surrogate).              │
├─────────────────────┼──────────────────────────────────────────────────┤
│ SIMULATED           │ Counterfactual output produced by parametric     │
│                     │ transit simulation engines (Little's Law).       │
├─────────────────────┼──────────────────────────────────────────────────┤
│ SYNTHETIC           │ Artificially generated test data for offline     │
│                     │ demonstration or UI component testing.           │
├─────────────────────┼──────────────────────────────────────────────────┤
│ UNAVAILABLE         │ No current data stream or cached record exists.  │
├─────────────────────┼──────────────────────────────────────────────────┤
│ AUTH_REQUIRED       │ External feed exists but requires private        │
│                     │ credentials or token access.                     │
└─────────────────────┴──────────────────────────────────────────────────┘
```

## 2. DETAILED CLASSIFICATION SPECIFICATIONS

### 2.1 OBSERVED
- **Definition:** Empirical data captured directly by calibrated hardware instruments or authorized human observers.
- **Examples:** Physical passenger boardings recorded at AIIMS bus stop during Phase 15 field surveys; GPS NMEA logs from active test vehicles.
- **Required Metadata:** Instrument/sensor ID, observer ID, exact UTC timestamp, geographic lat/lon with error radius.

### 2.2 VERIFIED_EXTERNAL
- **Definition:** Structured datasets released by municipal transit authorities and verified via cryptographic checksums or schema validation.
- **Examples:** OTD Delhi GTFS static schedule (`routes.txt`, `stops.txt`); CPCB official emissions factors.
- **Required Metadata:** Publishing organization, official portal URL, retrieval date, license terms, schema version.

### 2.3 DERIVED
- **Definition:** Deterministic mathematical transformations of observed or verified external records.
- **Examples:** Total journey travel time computed by summing walking segments and bus run times; corridor average speed computed from segment distances and transit times.
- **Required Metadata:** Transformation formula, input record references, mathematical units.

### 2.4 ESTIMATED
- **Definition:** Statistical approximations where complete observation is physically impossible or unrecorded.
- **Examples:** Commuter alightings inferred from Electronic Ticketing Machine (ETM) boarding records using trip-chaining algorithms; headway irregularity ($C_v$).
- **Required Metadata:** Sampling methodology, sample size ($N$), assumed error distribution, confidence intervals.

### 2.5 PREDICTED
- **Definition:** Outputs of probabilistic or machine learning models projecting transit states across future time horizons.
- **Examples:** 15, 30, and 45-minute forward crowding predictions along the Aurobindo Marg corridor generated by the Spatio-Temporal Graph Neural Network (ST-GNN).
- **Required Metadata:** Model architecture ID, training data range, Bayesian Credible Interval ($95\%$ PICP), Mean Absolute Error (MAE).

### 2.6 SIMULATED
- **Definition:** Counterfactual scenario evaluations testing hypothetical interventions.
- **Examples:** Evaluating wait-time reductions if 16 additional electric buses are added to Ring Road corridor with transit signal priority.
- **Required Metadata:** Baseline corridor ID, delta parameters ($\Delta$ buses, $\Delta$ headway), governing equations (Little's Law, price elasticity).

### 2.7 SYNTHETIC
- **Definition:** Programmatically generated mock records used exclusively for UI development, automated unit testing, or offline demonstration.
- **Examples:** Mock bus telemetry generated in test fixtures when external network connections are unavailable.
- **Required Metadata:** Fixture name, generator function, explicit synthetic disclaimer.

### 2.8 UNAVAILABLE
- **Definition:** Explicit state returned when data cannot be retrieved and no valid cache exists.
- **Examples:** Telemetry sensor dropped offline, API endpoint unreachable, network partition.
- **Required Metadata:** Reason for unavailability, last successful attempt, retry policy.

### 2.9 AUTH_REQUIRED
- **Definition:** Upstream feed is operational but gated by institutional credentials.
- **Examples:** Live Delhi OTD GTFS-Realtime Protocol Buffer feed requiring registered institutional API key.
- **Required Metadata:** Endpoint URL, required authorization method (`API_KEY_QUERY`), documentation link.

## 3. MATHEMATICAL NON-ELEVATION INVARIANT

The core epistemological guarantee of NEXBUS is defined by the elevation prevention function:
$$\text{preventClassificationElevation}(C_{\text{current}}, C_{\text{target}}) \to \{\text{allowed}, \text{reason}\}$$

| Current State | Target State | Permissibility | Reason |
| :--- | :--- | :--- | :--- |
| `SYNTHETIC` | `OBSERVED` | 🔴 **PROHIBITED** | Synthetic fixtures cannot become physical reality. |
| `SYNTHETIC` | `VERIFIED_EXTERNAL` | 🔴 **PROHIBITED** | Synthetic data cannot be labeled as official authority feeds. |
| `PREDICTED` | `OBSERVED` | 🔴 **PROHIBITED** | Model forecasts are probabilistic, not observed events. |
| `SIMULATED` | `OBSERVED` | 🔴 **PROHIBITED** | Hypothetical simulations cannot be substituted for actual operations. |
| `UNAVAILABLE`| `OBSERVED` | 🔴 **PROHIBITED** | Network outages cannot silently produce synthetic observations. |
| `OBSERVED` | `DERIVED` | 🟢 **PERMITTED** | Real observations may be mathematically aggregated. |
| `VERIFIED_EXTERNAL` | `DERIVED` | 🟢 **PERMITTED** | Official timetables may be used to calculate route distances. |
